# Дорожная карта

Утверждённый план проекта. Агенты: перед работой над этапом прочитайте его раздел и отметьте статус.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Хранилище | SQLite (WAL) как основное, импорт/экспорт форматов ST (JSONL, PNG/JSON карточки) |
| Пользователи | Один пользователь. Доступ по сети только по токену |
| Скрипты | Без STscript. Свои slash-команды, расширяемые плагинами |
| Расширения в ядре | Только regex-скрипты и суммаризация. Остальное (картинки, TTS, RAG, перевод, Quick Replies) плагинами |
| Зависимости | pip, закреплённые версии (`requirements.txt`), только чистый Python |
| Провайдеры | OpenAI-совместимые, Anthropic, Google Gemini, локальные (KoboldCpp, llama.cpp, Ollama, text-generation-webui) |
| Импорт из ST | Нужен импорт целой папки данных ST (`data/default-user`) |
| Контроль версий | git |
| Минимальный Python | 3.11 (Termux поставляет 3.12+) |

## Визуальный фундамент (этап 3а)

Цель владельца: интерфейс можно собирать под себя текстовыми просьбами к агенту (сейчас Claude Code по скилу, с этапа 8 помощник поверх чата). Нужны картинки, анимации, интерактив, вплоть до персонажа, собранного из частей. Нынешний интерфейс — заготовка. Основное устройство: планшет и маленький телефон. Решения владельца (2026-10-28):

1. **Темы.** Внешний вид задаётся переменными: цвета, шрифты, скругления, отступы, тени, фоны. Тема — папка в `data/themes/<имя>/` с CSS, картинками и необязательным скриптом эффектов. Переключение мгновенное, без перезагрузки. Нынешние светлая и тёмная становятся встроенными темами.
2. **Именованные места интерфейса.** Фон, шапка, боковая панель, рамка сообщения, аватар, панель ввода, диалоги имеют стабильные имена (атрибуты), документированные в скиле. Тема оформляет их без правки кода, обновления приложения тему не ломают.
3. **Слой сцены** за чатом: картинки и анимации темы. Сейчас только основа и пример.
4. **Библиотека картинок:** загрузка, просмотр, удаление. Темы ссылаются на картинки из неё.
5. **Генерация картинок:** отдельное подключение (адрес, ключ, модель) в OpenAI-совместимом формате, заглушка в fake LLM, кнопка «Сгенерировать» в библиотеке. Ключ в браузер не попадает.
6. **Безопасность:** безопасный режим (адрес со стандартной темой). Ошибка в скрипте темы не роняет страницу. Скрипт темы включается только с подтверждения.
7. **Сначала планшет и телефон:** раскладка под маленький экран. Анимации лёгкие (transform/opacity, без тяжёлых эффектов), учитывается `prefers-reduced-motion`.
8. **Скил `.claude/skills/make-theme/`:** места интерфейса, генерация картинок, анимации, бюджет производительности. Проверка: агент по скилу делает пример-тему с анимированной сценой.
9. **Тема персонажа:** общая тема по умолчанию, персонажу можно назначить свою.
10. **Обмен темами:** тема выгружается и загружается одним файлом с метаданными (имя, автор, версия, превью). Чужая тема со скриптом включается только после предупреждения. Позже, на этапе 11 или плагином: каталог тем (репозиторий GitHub или свой сервер) с установкой прямо из приложения.

## Движок промптов и персонажи (этап 4)

Решения владельца (2026-10-28):

1. **Персоны не отдельная сущность.** Есть один список персонажей (отдельная вкладка или открывающееся меню, главное — удобно). В чате любого персонажа можно отметить «я играю за него». У такого персонажа есть переключатель «модель может писать за него». Если выключено, модели отправляется запрет писать за этого персонажа. Запрет не отправляется, когда модель сама попросили написать за пользователя.
2. **Несколько персонажей в чате**, сколько угодно. У каждого два числа: глубина (сколько сообщений от конца чата вставить карточку: ближе к концу — сильнее влияет) и важность (кого выбросить первым, если промпт не влезает). Например, важный для сюжета сейчас — глубина 1, неважный — 8.
3. **Агенты и помощник** (этап 8) меняют глубину, важность и содержимое персонажей через те же сервисы, что и интерфейс. Каждое изменение публикует событие, чтобы плагины могли на него реагировать.
4. **Персонаж-дерево (4б).** Персонаж — это не одно поле карточки, а дерево блоков и подблоков (например «Волосы» с очень подробным описанием). Модель по умолчанию получает только основную карточку (обычно 1500–2500 токенов). Подблок подключается, когда тема всплыла в разговоре: по ключевым словам (всегда, мгновенно) и по смыслу через векторы (если подключён сервис векторов). В векторы попадает **только** текст блоков персонажа: не системный промпт, не лорбуки, не прочий мусор. Вид: списком или деревом «пузырями».
5. **Заметки автора (4в).** Три уровня: общая, у персонажа, у чата (каждая по желанию). Заметка — запись с глубиной, ролью (от кого), интервалом (каждые N сообщений) и режимом: невидимая и не сохраняется в истории или сохраняется в истории. Кнопки «показать невидимые заметки» и «очистить чат от невидимых заметок». Массовая правка заметок по номерам сообщений (`1-52 68-72`, `75 85`): удалить или изменить. «Изменить» открывает окно поверх чата: сообщение с номером и его заметка (или пометка «нет заметки»). При большом выборе сообщения показываются свёрнутыми. Агентам оставить возможность массовой правки через сервисы.
6. **Подсчёт токенов:** быстро и примерно при отправке, точно по кнопке в окне «что видела модель».
7. **Пресеты ST:** владелец даст свои файлы для проверки импорта (проверять на копиях).
8. Для тестов создаются персонажи-заглушки.
9. **История по умолчанию отправляется целиком** (обрезается только при нехватке места). «Что видела модель» хранится сжатым для последних ответов (число настраивается).

### Решения по этапу 4б (2026-10-28)

1. У каждого блока цветной кружок: голубой — отправлять всегда, зелёный — по поиску (ключевые слова, а если блок векторизован, то и по смыслу), серый — выключен. У блока есть глубина вставки и «от кого» (система, пользователь, ассистент).
2. Сработал подблок: модель получает только его (и его подблоки) с подписью-путём «Аня › Внешность › Волосы». Сработал пузырь-группа: уходит вся группа.
3. Ключевые слова пишутся вручную, название пузыря тоже считается словом, русские окончания учитываются. Кнопка «подобрать слова» отдаёт это модели. Агенты меняют слова через сервисы.
4. Сработавший блок держится N ответов, по умолчанию 3, у каждого блока своё N.
5. Поиск идёт по последним 3 сообщениям, на зелёные блоки до 2000 токенов. Это глобальные настройки (вкладка «Промпт»).
6. Векторы через отдельное подключение (как для картинок). Без него работают только слова.
7. Вид — карта: двигать и приближать пальцами, перетаскивать пузыри, пузырь может содержать пространство с подпузырями (вложенный вид) или соединяться линиями. Красиво и без лагов при большом числе пузырей. Есть и вид списком.
8. Импорт карточек ST: поля карточки остаются карточкой (корень дерева), записи встроенного лорбука с голубым кружком становятся голубыми пузырями, а с зелёным или «цепью» (векторы) — зелёными. При экспорте в ST собирается обратно.

### Решения по этапу 4в (2026-10-28)

1. Три вида заметок (уточнено владельцем после проверки). **Не сохраняется**: модель видит её только в том запросе, где она сработала, следов не остаётся. **Невидимая**: остаётся в истории после сообщения, модель видит её дальше, в чате она скрыта; «показать все невидимые» выводит их слева от сообщений. **Видимая**: остаётся в истории и висит справа от сообщения (статусы и прочее, что удобно отслеживать); сама сворачивается, когда после сообщения прошло 3 сообщения, и скрывается по ✕. У каждого сообщения кнопка 📝: показать или скрыть его заметки (и невидимые), а если заметки нет — написать её. На узком экране заметки идут под сообщением.
2. На каждом уровне (общие, у персонажа, у чата) список заметок, у каждой своя глубина, роль, интервал, режим и переключатель вкл/выкл.
3. Массовая правка по номерам сообщений умеет менять (и вид: видимая или невидимая), удалять и добавлять заметки (у сообщений с пометкой «нет заметки»), есть «одна заметка на все выбранные».
4. Кнопка 📝 в шапке чата рядом с 👥: вкладки «Чат», «Персонажи», «Общие», правка по номерам, «показать невидимые», «очистить». Общие заметки также во вкладке «Промпт» настроек.
5. Частота — «через N ответов»: 0 — на каждый ответ, 1 — через один. Ответы считаются по ветке (приветствие тоже ответ). Наш файл чата (JSONL) хранит заметки чата и заметки у сообщений. Импорта чатов SillyTavern пока нет, поэтому их заметка автора переносится вместе с ним (этап 11).

## Память и сжатие контекста (открытый вопрос, обсудить отдельно)

Владелец считает это самым важным вопросом проекта, фундаментом будущей системы агентов (агент-архитектор, суб-агенты за отдельных персонажей, которые помнят только свои мысли и мелкие детали). Решение ещё не принято. Варианты, названные владельцем:
- суммаризация нескольких сообщений в один блок поменьше;
- суммаризация каждого сообщения и сохранение её в векторную базу;
- полное сжатие и пересжатие с каждым сообщением;
- выгрузка чата в файл плюс суммаризация (как команда compact);
- векторная база без сжатия и со сжатием.

Требования: для каждого получателя (основная модель, архитектор, каждый суб-агент) отдельно настраивается, что ему отправлять (полные сообщения, суммаризации, результаты векторного поиска) и максимум токенов. Полные сообщения перегружают слабую модель, а суммаризация теряет мелкие детали, ради которых суб-агенты и существуют. Перед реализацией нужен отдельный разговор с владельцем и разбор подходов. Задел в 4а: блок «история чата» в менеджере промпта настраивается (целиком, последние N, лимит токенов), а пресет описывает всё, что получает один получатель, поэтому позже у каждого агента будет свой пресет.

## Требования агентного режима (заложить с этапа 1)

Цель: плагин «дерево мыслей» для RP. Несколько агентов думают за персонажей, окружение и сюжет, потом пишется итоговый ответ. Что для этого нужно от ядра:

1. **Многократные вызовы моделей.** Плагин вызывает `api.llm.generate(...)` сколько угодно раз, параллельно (`anyio` task group), с любым провайдером и моделью из профилей подключения.
2. **Замена конвейера генерации.** Конвейер генерации реализован как сменная стратегия `Generator`. Плагин регистрирует свою стратегию и может выполнить весь ход вместо стандартной, а может переиспользовать стандартные шаги (сборка промпта, лорбук).
3. **Хранилище плагина на чат** (таблица `plugin_data(plugin_id, chat_id, key, value)`) и **служебные сообщения** с флагами `hidden` (не показывать в чате) и `exclude_from_prompt` (не включать в промпт). У сообщения есть `owner` (id плагина).
4. **Ход работы в реальном времени.** Генерация публикует события трассировки (`trace`) в тот же SSE-поток. Frontend-часть плагина подписывается и рисует дерево в своей панели.
5. **Структурированный вывод.** Запрос к провайдеру принимает `response_format` (JSON Schema). Провайдеры используют нативный режим (OpenAI `json_schema`, Gemini `responseSchema`, Anthropic через tool use), иначе запасной вариант: инструкция в промпте + извлечение и проверка JSON.
6. **Лимиты и остановка.** Каждая генерация получает `RunBudget` (max_steps, max_cost, max_tokens, timeout) и `CancelScope`. Каждый вызов модели списывает usage и стоимость, при превышении лимита бросается `BudgetExceeded`. Кнопка «Стоп» в UI отменяет всё дерево вызовов.

7. **Персонажи по ходу сцены.** Агент сам приводит персонажа в чат (`cast.add_member`, событие `chat.members_changed`) и отдаёт ему ход (`speaker=`); заложено в 7а.

Где это реализуется:
- Этап 1: интерфейс провайдера (`usage`, отмена, поле `response_format`), сменная стратегия `Generator`, флаги сообщений в схеме, события `trace` в SSE.
- Этап 6: нативный структурированный вывод у всех провайдеров, таблица цен.
- Этап 8: `PluginAPI` (llm, storage, messages, trace, budget), скил `.claude/skills/agentic-plugin/`, проверочный плагин `plugins/example-agentic-rp/` с тестами на фейковом LLM.

## Помощник поверх чата (этап 8)

Отдельная панель вне чата: пользователь пишет помощнику, а тот инструментами меняет приложение. Например: «сделай CSS красивее», «напиши лорбук про город», «почисти историю чата». Решения владельца (2026-10-28):

| Вопрос | Решение |
|---|---|
| Доступ | Только данные (карточки, чаты, лорбуки, пресеты, настройки) и пользовательский слой `data/user/` (свой CSS и JS поверх интерфейса). Код ядра (`tavern/`, `web/`) помощник не трогает |
| Применение | Сразу. Каждое действие пишется в журнал и откатывается кнопкой «Отменить». Удаление и запуск пользовательского JS требуют подтверждения |
| Модель | Отдельное подключение в настройках, нужна модель с вызовом инструментов (function calling) |

Ограничения:
1. **Приложение не падает.** Инструменты вызывают те же сервисы, что и HTTP API, с теми же проверками. Пользовательский слой грузится после основного интерфейса, а ошибка в нём не ломает страницу. Есть «безопасный режим»: открыть приложение без пользовательского слоя.
2. **Откат.** Перед изменением снимается состояние затронутых объектов, журнал хранит действия по шагам.
3. **Секреты недоступны.** Нет инструмента, который читает `secrets.json` или API-ключи.
4. **Внедрение промпта.** Текст карточек, лорбуков и чатов — данные, а не команды. Разрушительные действия выполняются только после подтверждения пользователя.
5. **Лимиты.** Помощник работает с `RunBudget` и кнопкой «Стоп», как агентный режим.

Что заложить заранее:
- Этапы 4–5: логика пресетов, персон и лорбуков живёт в `services/`, а не в обработчиках HTTP, чтобы инструменты помощника вызывали её напрямую. Уже есть: `services/presets.py` (создать, изменить, удалить, импорт/экспорт пресетов — помощник должен уметь всё это, владелец просил 2026-10-28), `services/cast.py` (участники чата), `services/character_tree.py` (пузыри персонажа, ключевые слова, векторы). Каждое изменение публикует событие (`presets.changed`, `chat.members_changed`, `character.blocks_changed`) — журнал «Отменить» помощника подписывается на них.
- Этап 6: вызов инструментов (tools / function calling) в интерфейсе провайдера и в фейковом LLM.
- Этап 8: `services/assistant.py` (цикл инструментов), набор инструментов, журнал действий с откатом (миграция), панель в UI, `data/user/` с безопасным режимом, тесты на фейковом LLM.

### Этап 8: решения владельца (2026-10-31)

Порядок: 8а дополнения → 8б помощник → 8в «дерево мыслей».

8в, дерево мыслей (решено 2026-11-01): думают персонажи сцены и свой список думающих (по умолчанию
«Мир» и «Сюжет»); показ — свёрнуто под ответом и/или панель сбоку, выбор в настройках; модель — как
в чате, можно своё подключение и модель для думающих; один круг, можно до трёх; разрешение на
модели — галочкой вручную, как у всех дополнений.

8а, дополнения (ADR 0009):
1. Ставятся папкой в `data/plugins`, файлом и по ссылке GitHub с кнопкой «Проверить обновления».
2. Новое дополнение выключено. Не встроенное включается после окна: что оно о себе заявляет и
   предупреждение о полном доступе (в том числе к ключам). Встроенные — без вопросов.
3. Модели: только с разрешения (галочка, по умолчанию выключена), свой лимит (день, месяц, запросов на
   один ответ), расход отдельной строкой на вкладке «Расход», «спрашивать каждый раз» — всё в настройках.
4. Примеры: «🎲 Кубики» и «🌐 Перевод» — Google Переводчиком, не моделью («подключи сам»).

8б, помощник (уже решено):
1. Перетаскиваемое окно поверх чата, открывается кнопкой в меню.
2. Модель — та же, что в чате; в окне помощника можно сменить подключение или профиль.
3. Работает с любой моделью: шаги пишутся ответом по форме (структурированный вывод), действия
   выполняет Tavern. Встроенный вызов инструментов моделей не обязателен.
4. Список бесед, как у чатов; помощник знает, какой чат открыт.
5. Расход: своя строка «Помощник» на вкладке «Расход» и свои лимиты на день и месяц; общие тоже действуют.
6. Умения: персонажи и лорбуки, внешний вид, чаты, пресеты и настройки. Делается двумя частями:
   8б-1 — окно, беседы, журнал с «Отменить», подтверждение удаления, расход, персонажи и лорбуки;
   8б-2 — темы (вместо отдельного слоя `data/user/`: у тем уже есть версии и безопасный режим;
   тему со скриптом одобряет пользователь), чаты (сообщения, заметки), пресеты и настройки чата.
7. 8б-2 (решено 2026-11-01): помощник умеет всё, что человек может нажать на странице, — один общий
   инструмент вызывает те же запросы, что и интерфейс (каталог запросов с описаниями). «Отменить» для
   любого изменения: на время действия Tavern пишет изменённые строки базы (временные триггеры).
   Пока в каком-то чате пишется ответ, помощник ничего не меняет. Закрыто: ключи API, установка и
   включение дополнений, одобрение скриптов тем, сам помощник; удаление — после «Разрешить».
   Чат читает столько сообщений, сколько задано в его настройках (по умолчанию 50, можно весь), видит
   «что видела модель», рассуждения и расход. Темы: новая тема на основе текущей и сразу включается,
   встроенные не трогает, «Отменить» возвращает прежнюю. Пресеты: свой правит, встроенный — копия.
   «Скрыть от модели» появляется и у человека (метка на сообщении). Помощник может открыть чат или
   персонажа на странице, чтобы показать результат.

### Доработки после проверки владельцем (2026-10-29)

Заметки:
1. У сообщения сколько угодно заметок, видимых и невидимых. 📝 у сообщения открывает окно со всеми его заметками: читать, менять вид, удалять, добавлять.
2. Возле сообщения по умолчанию две последние заметки и плашка «ещё N»; в настройках можно «все подряд».
3. В правке по номерам «одна на все выбранные» добавляет заметку, а не заменяет; есть «все видимыми» / «все невидимыми».

Карта пузырей:
1. Пузырь при отпускании сразу встаёт на место (раньше на миг возвращался назад); пузыри отталкиваются и не налезают друг на друга.
2. «Куда» — поле только для цифр. Правки сохраняются сами. «Удалить» спрашивает подтверждение, в настройках можно отключить.
3. Связь проводится линией от «ушка» пузыря. Пузырь может висеть отцеплённым: он и вся его цепочка бледные и не уходят модели, пока их не прицепят к карточке.
4. Ссылка между пузырями разных групп (например «Руки › Пальцы» и «Ноги › Пальцы») — полупрозрачная дуга «вглубь». Когда один из них уходит модели, приходит и второй (только он и его подпузыри, не родители). Нужна, чтобы модель не путала похожие детали; раскроется на этапе 8.
5. Шанс у зелёных пузырей: не выпал — пузырь не придёт всё удержание (повторной генерацией его не «выбить»; удержание 0 — бросок каждый раз). Цвет линии показывает шанс. Шанс меняется разом для всех пузырей или для подпузырей одного пузыря. У голубых — «через N ответов» (0 — каждый).
6. Пузырь можно развернуть в отдельное пространство (двойное нажатие или «⤢»); позади остаётся размытое предыдущее, сверху путь для возврата. Вложение бросанием можно выключить, тогда пузыри только двигаются. У свёрнутого пузыря видна глубина вложенности.
7. История персонажа: каждое изменение карточки и пузырей (кроме положения на карте) — шаг, «↶ Отменить» без ограничения, версии создаются сами (закрыли персонажа или 10 минут тишины) и восстанавливаются целиком. Хранятся только прежние значения в сжатом виде. Включено по умолчанию, отключается в настройках.
8. Карточка при выгрузке несёт всё дерево целиком (вложенность, ссылки, шанс, отцеплённые пузыри) в отдельном поле, которое SillyTavern пропускает; SillyTavern по-прежнему получает плоский лорбук.
9. Пример: `docs/examples/mira-bubble-demo.json` (Мира) — загрузить через «Импорт карточки». Навык для агентов по оформлению карты: `.claude/skills/style-bubble-map`.
10. Проверено на 1500 пузырях: карта открывается за ~90 мс, прокрутка и перетаскивание 60 кадров/с, удаление ветки из 1500 пузырей 0,45 с, её отмена 0,2 с.

Вторая правка карты:
1. «Подобрать» не повторяет слова: ни уже добавленные, ни название, ни предложенные раньше для этого пузыря (с любыми окончаниями). Нет новых — спокойная подсказка.
2. Линия от «ушка» пузыря делает ссылку 🔗 (а не переносит пузырь). Перенос — перетаскиванием самого пузыря, отцепить — «✂ Отцепить».
3. Стрелки ▲▼ убраны. Порядок среди соседей — маленькая цифра в правом верхнем углу пузыря; в панели её можно ввести (поле «№»). Цифры в группе не повторяются: занятая — остальные сдвигаются. У подпузырей свой счёт внутри группы, у отцеплённых цифры нет. Модель читает соседей в этом порядке.
4. Исправлено: после строки «✓ …» над картой (шанс, векторы) пузыри пропадали до перезагрузки.

### Этап 5: лорбуки (решения владельца, 2026-10-29)

1. Лорбук — отдельная книга с той же картой пузырей, что у персонажа (цвета, слова, шанс, «держится», ссылки, цифры порядка, «⤢», список, история и «↶ Отменить»). Корень карты — сама книга. Движок один для персонажей и книг.
2. Раздел «ЛОРБУКИ» слева: список, «+ Лорбук», «Импорт лорбука», скачать, удалить; окно книги — название, описание (для себя), карта.
3. Четыре уровня работают вместе: общие (⚙ → Лорбуки), у чата (окно 👥), у персонажа (его карточка; работает и когда он «это я»). Одна книга, включённая дважды, срабатывает один раз. Порядок: книги чата, потом участников, потом общие.
4. Поиск: ключевые слова (окончания не важны), по смыслу (≈ векторы только из текста записей), цепочки — текст найденных записей и пузырей персонажей будит другие записи, до 2 шагов (меняется в настройках); у записи «не будит других» / «не будится другими».
5. «Ещё» в панели пузыря (свёрнуто; работает и у пузырей персонажей): название — тоже слово, вторые слова с «и хотя бы одно / и все / но ни одного / но не все», только целые слова, регистр, сколько сообщений смотреть, пауза после срабатывания, «не раньше ответа №», группа (приходит одна: держащаяся, главная или по весу), фильтр по персонажам, место в промпте.
6. Места: блоки пресета «Лор (до/после карточек)», у заметки автора сверху/снизу, у примеров диалога, на глубине N. Чему нет блока в пресете — идёт перед чатом.
7. Свой лимит: токены или % окна модели (⚙ → Лорбуки). Не влезло — первыми отпадают зелёные с большим номером; список виден в 👁 у ответа.
8. Файлы SillyTavern: импорт и экспорт без потерь (всё незнакомое возвращается на место), наш экспорт несёт и всё дерево. Карточка ST с именем лорбука получает эту книгу, если она есть.
9. Пример: `docs/examples/eira-world.json` (Мир Эйры). Скорость: 2000 записей с цепочками — ~70 мс подбора, книга открывается за ~0,4 с.

Правка после проверки (у персонажей и у книг):
1. «+ Подпузырь» и «+ Пузырь» больше не переключают панель на новый пузырь: остаётся открытым тот, где вы были, внизу спокойная подсказка, ветка в списке раскрывается. Переключение включается в ⚙ → «Основное» → «сразу открывать созданный пузырь».
2. «Список»: ветки сворачиваются (▸/▾), сначала открыт только верхний уровень; «Развернуть всё» / «Свернуть всё»; путь к выбранному пузырю раскрывается сам; открытые ветки запоминаются для каждого персонажа и книги.
3. Список больше не тормозит на тысячах записей: рисуются только видимые строки. На 3330 пузырях (три уровня): выбор строки 28 мс вместо 451, набор текста 14 мс на букву вместо 149, «Развернуть всё» 11 мс.
