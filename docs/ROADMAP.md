# Дорожная карта

Утверждённый план проекта. Агенты: перед работой над этапом прочитайте его раздел и отметьте статус.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Хранилище | SQLite (WAL) как основное, импорт/экспорт форматов ST (JSONL, PNG/JSON карточки) |
| Пользователи | Один пользователь. Доступ по сети только по токену |
| Скрипты | Без STscript. Свои slash-команды, расширяемые плагинами |
| Расширения в ядре | Только regex-скрипты и суммаризация. Остальное (картинки, TTS, RAG, перевод, Quick Replies) плагинами |
| Зависимости | pip, закреплённые версии (`requirements.txt`), только чистый Python |
| Провайдеры | OpenAI-совместимые, Anthropic, Google Gemini, локальные (KoboldCpp, llama.cpp, Ollama, text-generation-webui) |
| Импорт из ST | Нужен импорт целой папки данных ST (`data/default-user`) |
| Контроль версий | git |
| Минимальный Python | 3.11 (Termux поставляет 3.12+) |

## Требования агентного режима (заложить с этапа 1)

Цель: плагин «дерево мыслей» для RP. Несколько агентов думают за персонажей, окружение и сюжет, потом пишется итоговый ответ. Что для этого нужно от ядра:

1. **Многократные вызовы моделей.** Плагин вызывает `api.llm.generate(...)` сколько угодно раз, параллельно (`anyio` task group), с любым провайдером и моделью из профилей подключения.
2. **Замена конвейера генерации.** Конвейер генерации реализован как сменная стратегия `Generator`. Плагин регистрирует свою стратегию и может выполнить весь ход вместо стандартной, а может переиспользовать стандартные шаги (сборка промпта, лорбук).
3. **Хранилище плагина на чат** (таблица `plugin_data(plugin_id, chat_id, key, value)`) и **служебные сообщения** с флагами `hidden` (не показывать в чате) и `exclude_from_prompt` (не включать в промпт). У сообщения есть `owner` (id плагина).
4. **Ход работы в реальном времени.** Генерация публикует события трассировки (`trace`) в тот же SSE-поток. Frontend-часть плагина подписывается и рисует дерево в своей панели.
5. **Структурированный вывод.** Запрос к провайдеру принимает `response_format` (JSON Schema). Провайдеры используют нативный режим (OpenAI `json_schema`, Gemini `responseSchema`, Anthropic через tool use), иначе запасной вариант: инструкция в промпте + извлечение и проверка JSON.
6. **Лимиты и остановка.** Каждая генерация получает `RunBudget` (max_steps, max_cost, max_tokens, timeout) и `CancelScope`. Каждый вызов модели списывает usage и стоимость, при превышении лимита бросается `BudgetExceeded`. Кнопка «Стоп» в UI отменяет всё дерево вызовов.

Где это реализуется:
- Этап 1: интерфейс провайдера (`usage`, отмена, поле `response_format`), сменная стратегия `Generator`, флаги сообщений в схеме, события `trace` в SSE.
- Этап 6: нативный структурированный вывод у всех провайдеров, таблица цен.
- Этап 8: `PluginAPI` (llm, storage, messages, trace, budget), скил `.claude/skills/agentic-plugin/`, проверочный плагин `plugins/example-agentic-rp/` с тестами на фейковом LLM.
